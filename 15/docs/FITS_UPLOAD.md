# Local FITS observations

Choose **Upload Observations** inside the comparator, then **Upload A** and **Upload B**. One file previews immediately. **Compare** checks the metadata, quality, wavelength and sky overlap before enabling an aligned blink. Files are processed in a dedicated local browser worker and are not uploaded to a server. A failed comparison keeps both native previews visible and explains its blockers.

## Supported variants and limits

- Uncompressed FITS files, at most **64 MiB each**; selected science image at most **4,194,304 pixels** (for example 2048 × 2048). Parsing and comparison each have a 45-second worker time limit. Previews and comparisons are bounded to 512 pixels per side.
- Real two-dimensional primary or image-extension data. The reader prefers `IMAGE`, then `SCI`, then a primary image. It traverses 2880-byte FITS headers and HDUs and reads big-endian BITPIX 8, 16, 32, -32 and -64 science pixels, applying `BSCALE`, `BZERO`, `BLANK` and nonfinite masks. 64-bit integer science pixels are rejected to avoid integer precision loss.
- Native DR1/QR3-style **RICE_1-compressed FLAGS** in a binary-table HDU are decoded: 32-bit masks, full-width one-row tiles, `1PB` or `1QB` descriptors, bounded table/heap reads and block size 1–1024. The decoder was checked against Astropy for both full 2040 × 2040 real archive masks and a bundled independent compressed fixture. Other compressed science/mask variants are unsupported; a valid uncompressed science image still previews with a warning if its auxiliary mask cannot be decoded.
- SPHEREx-style `IMAGE`, `FLAGS`, `VARIANCE`, plus aligned `CWAVE` and `CBAND` image extensions. Calibrated wavelength maps must declare supported length units (`um`, `nm`, `m`, `angstrom`); they are converted to micrometres. Native SPHEREx `WCS-WAVE` tables alone are **not** treated as calibrated CWAVE/CBAND maps.
- Celestial WCS: RA/Dec in degrees, ICRS or explicitly FK5/J2000, `RA---TAN` / `DEC--TAN` and `TAN-SIP`, using CD or PC+CDELT matrices. SIP forward distortion and iterative inverse are implemented. Alternate spectral WCS does not replace the celestial WCS. Other projections, TPV, non-J2000 FK5, nondegree celestial units, lookup distortion, cubes, and gzip-compressed whole files are not supported for aligned blink. Unsupported WCS can still have a truthful native-pixel science preview.
- Quality flags use the product's own `MP_*` or `MSKNnnnn` / `MSKMnnnn` definitions. Only the named neutral `SOURCE` and `FULLSAMPLE` bits are accepted. All other bits, nonfinite science values, and nonpositive/nonfinite variance are masked. Missing flag definitions block scientific blink.

Metadata comes from headers and extension values, not the selected filename. The interface reports absent information. `DATE-OBS` and `MJD-OBS`, where supplied, must agree within 1.1 seconds; blink requires explicit UTC `TIMESYS`. A generic processing `DATE` is not an observation timestamp. Release, processing version, detector and calibrated science units must be present and match. Attached calibration identifiers, when present, must also match. No release is inferred from a filename or guessed from dates.

## Why comparison may be unavailable

The pair needs distinct observation times, supported celestial WCS in the same reference frame, matching release/calibration/detector/units, positive variance and defined quality flags, and calibrated wavelength and bandwidth. At least 5% of the reference field and at least 64 common unflagged compatible pixels must remain. Different wavelength pixels are masked in both frames. More than 10% incompatible wavelengths among otherwise common usable pixels blocks blink.

Each output pixel samples both inputs at the same sky direction using TAN/SIP WCS. The output is north-up/east-left with the same field, orientation and mask for both dates. Wavelength compatibility is checked **at each output sky pixel**: central wavelength difference ≤ one quarter of the narrower bandwidth and bandwidth ratio ≤1.1. The common geometric footprint is cropped. Bilinear interpolation uses only valid source pixels. The shared display uses the combined 1st–99.5th percentiles; the UI applies the same asinh stretch, brightness and contrast to both. Original science values are not background-normalized or altered by a photometric fit.

This is a visual comparison, not a difference-image analysis or a motion measurement. Spatially varying PSFs, zodiacal/other backgrounds and correlated calibration noise can differ. Variance is used to reject invalid pixels, not to compute a validated significance image. No PSF matching, proper-motion fit or Planet X detection is claimed.

## Genuine downloadable examples

`/samples/rw-aurigae-A.fits` and `/samples/rw-aurigae-B.fits` are small real DR1 native-pixel cutouts. They preserve science values, variance, flags, celestial SIP and dates; calibrated CWAVE/CBAND maps are attached from the matched official calibration product. Their native orientations differ, so successful upload comparison also exercises celestial reprojection. The files are **derived cutouts**, not unmodified full-detector archive files. `/samples/provenance.json` records official URLs, hashes and exact derivation; `/samples/wcs-reference.json` contains independently computed Astropy coordinate truth used in parser tests. Added `RELEASE` and calibration-provenance keywords describe the verified source provenance.

A raw native SPHEREx image can be previewed within the size limit. A raw native product normally lacks attached CWAVE/CBAND calibration and an explicit release keyword; upload blink therefore remains unavailable until a scientifically prepared cutout carries those documented fields. The included Python data-processing scripts remain the reproducible preparation route; the browser does not guess a missing spatial wavelength calibration or fetch one silently.
